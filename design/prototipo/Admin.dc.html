Uso por uma única pessoa. Controles no tamanho sm (36 px), coluna de 1200 px, DataTable e Pagination do design system. No mobile, a tabela agrupa as colunas numa célula para caber em 390 px.

Lacunas do design system (sinalizadas, não inventadas) 1. Selo "Em destaque": não existe variante. Usa as classes rn-badge + rn-badge--text + rn-badge__dot; o ponto o diferencia do badge de tipo Texto. 2. Botão destrutivo: não existe variante "danger". A confirmação de exclusão usa o Button primário com ícone de lixeira. 3. Editor rich text: não há componente. Barra montada com Button ghost sm; o Icon não tem glifos de negrito, itálico, lista, link, citação, imagem e título, então os botões usam rótulo em texto. 4. Área de upload (arrastar e soltar) e barra de progresso: não existem. Upload usa o Input type="file" (como no UI kit) e o estado de envio usa o Icon loader com a classe rn-spinner. 5. Seletor de tipo: não há controle segmentado. Usa dois Button sm com aria-pressed, como no UI kit. 6. Textarea (resumo): não há componente. Usa a classe rn-input num <textarea>, como no UI kit. 7. Menu "⋯" das ações no mobile: não existe componente de menu, e o Icon não tem reticências (o DS proíbe usar caractere unicode como ícone). O gatilho é um Button secundário "Ações" de 44 px, que abre as ações no Modal em tela cheia. Veja os frames "menu de ações". 8. Cards da lista no mobile: não há componente de card de linha. Usam a superfície, a borda, o raio e a sombra de card do DS, com os mesmos campos da tabela. 9. Filtros: as telas desktop não têm filtros, então nada foi criado no mobile. Só "Exportar CSV" e "Reenviar falhas" ficam no topo, com largura total. 10. Pagination: o componente usa botões sm de 36 px, abaixo dos 44 px pedidos para toque. Não foi alterado.
